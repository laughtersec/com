To test our COM server, we will build the `UserInfoClient` application. The `UserInfoClient` application will create and use the `UserInfo` COM object that we've just developed. Once the `UserInfo` object is created, we will use `QueryInterface` to change to the `IUserInfo` interface, which we will then use to set each of the `UserInfo` object's properties. After setting each property, we will retrieve, format and display their values via the Win32 API function `MessageBox`, which simply creates and displays a small window containing a message. We must recall what a COM client needs to do before doing all this:

- Initializing [the COM library](https://learn.microsoft.com/en-us/windows/win32/com/the-com-library) 
- Obtaining initial and subsequent interfaces
- Manipulating the COM object (as discussed)
- Release the COM object when it is no longer needed. 
- Un-initializing the COM library.

I'll demonstrate how to use in-process servers and out-of-process servers.
# In-Process

## Initializing the COM library

This will be done via the `CoInitialize` function, which is provided by COM to initialize the COM library and must be called before any other COM library calls ==except the== `CoGetMalloc` ==function and memory allocation calls.==

```cpp
//  Initialize COM library
hr = CoInitialize(NULL);
if (SUCCEEDED(hr))
{
	//<...>
}
```

## Obtaining an Initial Interface

We can now obtain the initial interface pointer to the `UserInfo` object. ==The pointer can be obtained in several different ways==, the most popular of which is to call `CoCreateInstance`. ==The client will call this function with the CLSID of our COM object and request a pointer to its `IUnknown` interface.== However, in order to resolve both the `CLSID_UserInfo` constant and the definition of the `IUserInfo` interface, the `UserInfoClient` application must include `UserInfo_i.c` and `UserInfo_i.h` files (generated by MIDL.exe upon passing `UserInfo.idl` as seen before). Since we are working with an inprocess server, we will use the [`CLSCTX_INPROC_SERVER`](https://learn.microsoft.com/en-us/windows/win32/api/wtypesbase/ne-wtypesbase-clsctx) class execution context constant with `CoCreateInstance`.

```cpp
hr = CoCreateInstance(CLSID_UserInfo, NULL, CLSCTX_INPROC_SERVER, IID_IUnknown, (LPVOID *)&pIUnknown);
if (SUCCEEDED(hr))
{
	//<...>
}
```

## Manipulating a COM object

Upon the successful call on `CoCreateInstance`, ==a pointer to the `IUnknown` interface of our COM object will be obtained==. Using this we can manipulate the COM object, and a simple [`QueryInterface`](https://learn.microsoft.com/en-us/cpp/atl/queryinterface?view=msvc-170) call requesting the `IID_IUserInfo` pointer is all it takes to obtain a pointer to the `IUserInfo` interface. By doing this, we can then set any of the available properties.

## Releasing the COM Object

The `Release` function can be called to destroy all the outstanding interface pointers on the `IUserInfo` object, which includes one `IUnknown pointer` and one `IUserInfo` pointer. The `UserInfo` object then destroys itself.

```cpp
//  Release the IUserInfo interface
pIUserInfo->Release();
//  Release the IUnknown interface
pIUnknown->Release();
```

## Uninitialize the COM library

After releasing the `UserInfo` COM object, the `UserInfoClient` prepares to terminate itself by uninitializing the COM library with a call to `CoUninitialize`. Every successful call to `CoInitialize` must be matched with a call to `CoUninitialize`. Once `CoUninitialize` has been called, no other COM APIs should be called, with the exception of the `CoGetMalloc` function and the memory allocation calls.

```cpp
//  Shut down the COM library
CoUninitialize();
```
